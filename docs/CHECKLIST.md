# Чек-лист демо · за 20 минут до питча

## 0. Проверка одной командой

```bash
python tools/verify_demo.py
```

Ожидаемо: строка `RESULT: all checks passed`. Если есть `[FAIL]` — сначала
исправить, потом показывать. Скрипт поднимает свой бэкенд, ваш не мешает.

## 1. Бэкенд

```bash
cd repo
python backend/server.py
```

Проверка (в браузере ноутбука):

- `http://localhost:8080/api/health` → `{"status":"ok"}`
- `http://localhost:8080/` → список QR-страниц
- `http://localhost:8080/qr/PUMP-402` → большой QR на весь экран

Оставить вкладку с QR открытой. Бэкенд не требует интернета и зависимостей.

## 2. Телефон (основной сценарий, настоящий AR)

1. Установить APK:
   `adb install -r app/build/outputs/apk/debug/app-debug.apk`
2. Телефон и ноутбук — в одной Wi-Fi сети.
3. Узнать IP ноутбука: `ipconfig` → IPv4 (например `192.168.1.42`).
4. В приложении: **Сканер → «Сеть»** → `http://192.168.1.42:8080/` → сохранить.
5. **Демо-режим выключить** — чтобы жюри видело реальные запросы.
   Включить обратно, если Wi-Fi на сцене заблокирован.
6. Разрешить камеру.
7. Навести на QR `PUMP-402` (или нажать чип `PUMP-402`).

Ожидаемо: переход в AR, 6 маркеров узлов, бейдж `AR`. Кнопка
«Запустить ИИ-сканирование» → 2 маркера краснеют → тап по маркеру →
BottomSheet → статус → «Зафиксировать акт» → PDF.

## 3. Эмулятор (страховка, SIM AR)

```powershell
emulator.exe -avd "Medium_Phone_API_36.1" -no-boot-anim -gpu auto -camera-back virtualscene
```

- Адрес API для эмулятора: `http://10.0.2.2:8080/` (по умолчанию).
- ARCore на эмуляторе не работает → приложение само включает **SIM AR**:
  маркеры, оверлей и акт работают, в шапке бейдж `SIM AR`.
- Быстрый вход в сцену без камеры:
  `adb shell am start -n ru.cyber102.arinspector/.MainActivity --es equipment_id PUMP-402`

## 4. Печать QR

`demo/qr/print.html` — открыть в браузере, печать **100% без масштабирования**
(«Actual size»). Готовые PNG: `demo/qr/PUMP-402.png`, `PUMP-118.png`, `VALVE-77.png`.
Поля вокруг кода не обрезать — иначе ML Kit не прочитает.

## 5. Проверка актов (для жюри)

```bash
curl http://localhost:8080/api/reports
```

Показывает сохранённые акты: номер, оборудование, статус. Это доказательство,
что «Зафиксировать акт» пишет на сервер, а не рисует заглушку.

## 6. Если что-то сломалось

| Симптом | Действие |
|---|---|
| Wi-Fi недоступен | включить **Демо-режим**, сценарий не меняется |
| QR не читается | чипы `PUMP-402` / `PUMP-118` / `VALVE-77` или ручной ввод |
| ARCore не завёлся | приложение само переходит в `SIM AR` — продолжаем |
| Камера занята | полностью закрыть приложение и открыть снова |
| Сервер перезапускали | акты в памяти сброшюруются, это нормально для мока |

## 7. Что говорить про ИИ (честно)

«Мобильная часть и контракт готовы полностью. Vision-модель подключается
заменой одного URL — сейчас в демо заранее подготовленные ответы, чтобы показ
не зависел от нагрузки на сеть».

## 8. Финальная репетиция (2 минуты)

1. QR → AR.
2. ИИ-сканирование → дефекты.
3. Красный маркер → карточка.
4. «Требует заказа запчастей» → акт → PDF.
5. Показать `/api/reports` на ноутбуке.
