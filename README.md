# ПромСкан

Система промышленного зрения для **КСТ Энерго**. Камера смотрит на узел оборудования, нейросети находят **коррозию, дефекты сварных швов и утечки масла**, система выдаёт заключение и создаёт заявку на ремонт. Заявку ведёт диспетчер, выполняет рабочий.

## Из чего состоит

| Часть | Стек | Где |
|---|---|---|
| Веб-панель | React 19, TypeScript, Vite, Tailwind | `src/` (актуальная версия в ветке `newfront`) |
| Бэкенд | FastAPI, ultralytics YOLO, SQLite | `app/` |
| Мобильное приложение | Kotlin, Jetpack Compose, CameraX, ML Kit | `mobile/` |
| Старый Android-клиент «AR-Инспектор» | Kotlin, Compose | `app/src/main/java/` (устаревший, не развивается) |

```
Камера (веб или телефон) ─ кадр ─► Бэкенд ─► YOLO: коррозия / сварка / масло ─► дефекты на кадре
                                       │
                                       ▼
                    критичность, причина, рекомендации (LLM или шаблоны)
                                       │
                       «Создать заявку» ─► Диспетчер ─► Рабочий
```

## Быстрый старт

### Бэкенд

Нужны Python 3.11+, GPU с CUDA и файлы моделей в `weights/` (в git не хранятся):
`defects_yolo.onnx` (одна обученная модель: сварка, трещины, масло, ржавчина; лежит в репозитории).

```bash
pip install -r requirements.txt
cp .env.production.example .env
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Проверка: `GET http://127.0.0.1:8000/health`. Подробности пайплайна: [`TOIR_PIPELINE.md`](TOIR_PIPELINE.md).

Настройки в переменных окружения (секреты не коммитить):

| Переменная | Назначение |
|---|---|
| `TOIR_ACCESS_KEY_HASH` | хеш ключа доступа |
| `TOIR_CORS_ORIGINS` | разрешённые источники для веб-панели |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM` | отправка писем с ключами |
| `OLLAMA_MODEL`, `OLLAMA_URL` | локальная LLM из Ollama для подробного анализа (приоритет над облаком), по умолчанию `http://127.0.0.1:11434` |
| `GEMINI_API_KEY` или `OPENAI_API_KEY` | облачная LLM, запасной вариант |
| `CORROSION_WEIGHTS`, `OIL_WEIGHTS`, `WELDING_WEIGHTS` | пути к весам; по умолчанию берётся `corrosion_yolo26.pt` / `oil_yolo26.pt`, если файлы есть, иначе прежние |

### Веб-панель

```bash
npm install
npm run dev:lan
```

В `.env` панели: `VITE_USE_MOCK_API=false`, `VITE_API_BASE_URL=/front`. Dev-сервер проксирует `/front` и `/static` на `127.0.0.1:8000`. Камере нужен HTTPS, поэтому `dev:lan` запускается с самоподписанным сертификатом.

### Мобильное приложение

См. [`mobile/README.md`](mobile/README.md). Нужны JDK 21 и Android SDK, `debug.keystore` создаётся один раз по инструкции. Адрес сервера вводится в настройках приложения: `http://<IP компьютера>:8000/`.

## API

| Префикс | Назначение | Авторизация |
|---|---|---|
| `/api/auth/*` | вход по ключу, сессия | Bearer |
| `/api/detect` | живое обнаружение дефектов (JPEG) | Bearer |
| `/api/equipment`, `/api/inspect`, `/api/reports` | основной API | Bearer |
| `/front/api/*` | маршруты веб-панели и мобильного приложения: оборудование, осмотр, подробный анализ, заявки, письма | нет |

Контракт веб-панели: [`docs/API_CONTRACT.md`](docs/API_CONTRACT.md). Координаты дефектов нормализованы `0..1`.

## Роли

| Роль | Доступ |
|---|---|
| `director` | сканер, панель, сотрудники, ключи администраторов |
| `admin` | сканер, панель, сотрудники |
| `dispatcher` | сканер, панель дефектов |
| `engineer` | сканер, своя задача |

## Ограничения

- Модели находят только коррозию, сварные дефекты и утечки масла. Остальные классы оборудования (двигатели, арматура, трансформаторы, конвейеры, теплообменники, компрессоры) в планах: Gemini vision и YOLO-World.
- Маршруты `/front/api/*` не требуют авторизации, письма ограничены 30 в час.
- В быстром осмотре заключение формируется по шаблонам, LLM работает в подробном анализе.
- Управление сотрудниками есть только в веб-панели, у него нет серверного API.
