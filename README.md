# ПромСкан

Веб-панель промышленного зрения для **КСТ Энерго**. Камера смотрит на узел оборудования, нейросети находят **коррозию, дефекты сварных швов и утечки масла**, система выдаёт заключение и создаёт заявку на ремонт. Заявку ведёт диспетчер, выполняет рабочий.

React + TypeScript + Vite + Tailwind. Бэкенд (FastAPI + YOLO) лежит в соседней ветке, см. [раздел 4](#4-бэкенд).

## 1. Как это работает

```
Камера в браузере ─ кадр раз в ~2 с ─► Бэкенд ─► 3 модели YOLO ─► дефекты поверх видео
                                          │
                                          ▼
                       критичность, причина, рекомендации
                                          │
              «Передать задачу» ─► Диспетчер ─► Рабочий (ссылка /task/<id>)
```

- **Сканер** отправляет кадры на `/front/api/inspect`. Ответ рисуется поверх видео.
- **Подробный анализ** запрашивает экспертное заключение по найденным дефектам.
- **Заявка** создаётся из результата осмотра и попадает в панель диспетчера. Исполнителя выбирают при передаче задачи в сканере, диспетчер следит за заявками, рабочий открывает карточку по ссылке и меняет статус `open → in_progress → closed`.
- **Вход** по личному 10-значному ключу, паролей нет. Директор создаёт сотрудника, ключ уходит ему на email.

Без бэкенда панель работает в демо-режиме на заглушках из `src/lib/inspection.ts`.

## 2. Быстрый старт

Нужны Node.js и npm.

```bash
npm install
npm run dev
```

Открыть <http://127.0.0.1:5173/>. `.env` не обязателен: по умолчанию включён mock-режим.

Демо-ключи для входа в репозиторий не публикуются, их выдаёт команда проекта.

**Проверка с телефона в локальной сети:**

```bash
npm run dev:lan
```

Vite напечатает `Network: https://<IP>:5173/`. Сертификат самоподписанный, браузер один раз покажет предупреждение. HTTPS обязателен: по `http://` браузер отключает камеру и WebCrypto (проверку ключа).

**Команды:**

| Команда | Что делает |
|---|---|
| `npm run dev` | dev-сервер на 127.0.0.1:5173 |
| `npm run dev:lan` | то же, доступно по сети через HTTPS |
| `npm run build` | `tsc --noEmit` и сборка Vite |
| `npm run test:run` | все тесты один раз |

Мобильная карточка задачи открывается по прямой ссылке `/task/<id>` без входа в панель.

## 3. Возможности и роли

| Роль | Доступ |
|---|---|
| Директор (`director`) | сканер, панель диспетчера, сотрудники, ключи (включая администраторов) |
| Администратор (`admin`) | сканер, панель диспетчера, сотрудники (диспетчеры и рабочие) |
| Диспетчер (`dispatcher`) | сканер, панель дефектов |
| Рабочий (`engineer`) | только сканер и карточка своей задачи |

Недоступный раздел показывает экран 403. Сессия лежит в `sessionStorage` и живёт в пределах вкладки.

**Разделы:**

- **Веб-сканер** (`/scanner`): камера с переключением и полноэкранным режимом, загрузка фото, выбор оборудования, паспорт узла при наведении, живые параметры (ржавчина, масло, сварка), подробный анализ, передача задачи.
- **Панель диспетчера** (`/defects`): список заявок со статусами и исполнителями, счётчики критичных, в работе и закрытых.
- **Сотрудники** (`/users`): создание, перевыпуск ключа, статус приглашения.
- **Карточка задачи** (`/task/:id`): мобильный экран «взял в работу → выполнил».

## 4. Бэкенд

Бэкенд находится в этом же репозитории, в ветке `feat/android-backend`. Это FastAPI-сервис на Python:

- **Модели:** `corrosion_yolov11_seg.pt` (коррозия, сегментация), `welding_yolov8_det.pt` (сварные швы, детекция), `oil_leaks.pt` (утечки масла, сегментация). Файлы `.pt` в git не хранятся, лежат в `weights/`.
- **LLM-эксперт** (`llm_expert.py`): по оборудованию, возрасту узла и дефектам выдаёт критичность, причину и рекомендации. Нужен `GEMINI_API_KEY` или `OPENAI_API_KEY`. Быстрый осмотр формирует заключение по шаблонам.
- **Запуск:** `uvicorn app.main:app --host 127.0.0.1 --port 8000` (нужна GPU и окружение с ultralytics и torch).

Маршруты, совместимые с этой панелью, смонтированы под `/front/api`:

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/equipment`, `/equipment/{id}` | оборудование и узлы |
| POST | `/inspect` | осмотр кадра, дефекты и заключение |
| POST | `/inspect/detailed` | подробный анализ с LLM |
| GET, POST | `/reports` | список и создание заявок |
| GET | `/reports/{id}` | карточка заявки |
| PATCH | `/reports/{id}/status` | смена статуса |
| POST | `/mail/access-key` | письмо с ключом доступа |

Подключение панели к бэкенду, файл `.env`:

```bash
VITE_USE_MOCK_API=false
VITE_API_BASE_URL=/front
```

В dev-режиме `vite.config.ts` проксирует `/front` и `/static` на `http://127.0.0.1:8000`, поэтому панель и API работают с одного origin (нужно для HTTPS в локальной сети).

Полные схемы запросов и ответов: [`docs/API_CONTRACT.md`](docs/API_CONTRACT.md). Координаты дефектов нормализованы `0..1`, начало в левом верхнем углу.

## 5. Письма с ключами

При создании сотрудника и при перевыпуске ключа панель вызывает `POST /front/api/mail/access-key`, бэкенд отправляет письмо по SMTP. Доступы задаются переменными окружения бэкенда:

| Переменная | Назначение |
|---|---|
| `SMTP_HOST`, `SMTP_PORT` | сервер, порт 465 (SSL) или 587 (STARTTLS) |
| `SMTP_USER`, `SMTP_PASSWORD` | логин и пароль приложения |
| `SMTP_FROM` | адрес отправителя |
| `SMTP_MAX_PER_HOUR` | лимит писем в час, по умолчанию 30 |

Если SMTP не настроен, бэкенд отвечает 503, а приглашение сотрудника получает статус `failed` с текстом ошибки. В mock-режиме письмо кладётся в демо-outbox в `localStorage`, интерфейс его не показывает. Ключ в журналы не пишется.

## 7. Переменные окружения

Панель (Vite). `VITE_*` попадают в клиентский bundle, секреты сюда не класть.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `VITE_USE_MOCK_API` | `true` | ровно `false` включает HTTP-запросы к бэкенду |
| `VITE_API_BASE_URL` | `http://127.0.0.1:8000` | адрес API; для dev с проксированием `/front` |

Шаблон: [`.env.example`](.env.example). После изменения перезапустите Vite.

Бэкенд: `TOIR_ACCESS_KEY_HASH`, `TOIR_CORS_ORIGINS`, `SMTP_*`, `GEMINI_API_KEY`, `OPENAI_API_KEY`. Значения хранятся только на сервере и не коммитятся.

## 8. Проверка качества

```bash
npm run test:run
npm run build
```

Тесты (vitest + Testing Library) покрывают API-клиент, маршруты и роли, вход и ключи, сотрудников, сканер, панель дефектов, карточку задачи и отправку писем. При запуске тестов mock-режим включается принудительно, настройки `.env` на них не влияют.

Тесты проверяют панель, но не работу реальных моделей: интеграцию с бэкендом нужно проверять вручную.

## 9. Безопасность и ограничения

- Вход проверяется в браузере: в `localStorage` хранятся только соль и PBKDF2-хеш. Это демо-модель. Для боевого режима проверку ключа и сессию нужно выполнять на сервере.
- Ключ создаётся в браузере и передаётся бэкенду для письма. В боевом режиме ключ должен создавать сервер.
- Эндпоинты `/front/api` не требуют авторизации. Письма защищены только лимитом в час и жёстким шаблоном.
- Сотрудники, созданные через интерфейс, хранятся в браузере, где их создали.
- В быстром осмотре заключение формируется по шаблонам, а не LLM.
