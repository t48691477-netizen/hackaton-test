# Скиллы проекта

Набор повторяемых инструкций для ИИ-агентов и людей. Каждый скилл — папка в
`.opencode/skills/<id>/SKILL.md`. OpenCode подхватывает их автоматически из
проекта; вручную можно загрузить упоминанием `@<id>`.

| Скилл | Когда включать | Что даёт |
|---|---|---|
| [`ui-review`](ui-review/SKILL.md) | любое изменение UI, цветов, типографики | чек-лист контраста, размеров целей, статусов; список запрещённых приёмов |
| [`build-verify`](build-verify/SKILL.md) | после любой правки кода, перед пушем | точные команды сборки, чтение лога `AR-Inspector`, известные ловушки |
| [`backend-live-ai`](backend-live-ai/SKILL.md) | работа с `/api/inspect`, `/api/chat`, ключами | режимы mock/live, подключение провайдера, проверка отката |

## Как добавить свой

```text
.opencode/skills/my-skill/
├── SKILL.md          # frontmatter + инструкции
├── scripts/          # опционально
└── references/       # опционально
```

```markdown
---
name: Human Readable Name
description: Одно предложение — когда агент должен это загрузить.
---
```

Требования:

1. `description` обязателен - без него скилл не показывается модели.
2. Пути внутри скилла относительны папке со `SKILL.md`.
3. Проверенные команды, а не догадки. Если что-то не проверено — так и пиши.
4. Никаких секретов и ключей.

## Почему в скиллах так подробно про «нельзя»

Каждый скилл здесь появился после реальной ошибки в этом проекте:

- дубли компонентов при правке файла (две `ThumbAction` в одном файле);
- «строительный» вид после того, как HUD-приёмы размножились на все экраны;
- падение обработчика бэкенда на кириллице в консоли Windows;
- эмулятор, убитый по памяти посреди проверки.

Инструкции хранят эти выводы, чтобы следующая модель не наступила туда же.
